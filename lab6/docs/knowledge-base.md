## 1. Розподілені обчислювальні системи (лекція 2.1)

- **Розподілена обчислювальна система** — набір обчислювальних вузлів, що координують роботу через **обмін повідомленнями** (синхронний або асинхронний).
- Приклади контекстів: системи з розподіленими ресурсами, розподілена пам’ять, хмарні та грід-системи.
- **Архітектури:** клієнт–сервер; **peer-to-peer** з рівноправними вузлами; варіанти зі спільною або розподіленою пам’яттю, гібридні.
- **Моделі паралелізму** (взаємодія процесів): спільна пам’ять; **передача повідомлень**; неявна взаємодія. За розподілом підзадач: паралелізм даних, задач, неявний паралелізм.
- У курсі для розподілених обчислень акцент на **MPI** (зокрема **Open MPI**).

## 2. Стандарт MPI (лекція 2.2)

- **MPI** — це **специфікація**, а не одна бібліотека; описує набір процедур для **передачі повідомлень** між паралельними процесами.
- Цілі: практичність, портабельність, ефективність, гнучкість. Специфікації прив’язані до **C** та **Fortran**; реалізації можуть відрізнятися за версією стандарту.
- **Open MPI** — поширена відкрита реалізація MPI для C; типовий стек на Linux-кластерах: `mpicc`, `mpiexec`/`mpirun`.

### Життєвий цикл і оточення

- `MPI_Init` — ініціалізація (один раз на процес, до інших викликів MPI).
- `MPI_Finalize` — завершення (останній виклик MPI у програмі).
- `MPI_Initialized` — перевірка, чи вже викликано `MPI_Init`.
- `MPI_Comm_size(comm, &size)` — кількість процесів у комунікаторі (для `MPI_COMM_WORLD` — усі процеси програми).
- `MPI_Comm_rank(comm, &rank)` — унікальний **ранг** процесу (зазвичай `0 … size-1`), використовується для адресації та гілкування логіки.
- `MPI_COMM_WORLD` — комунікатор «усі процеси» за замовчуванням.
- `MPI_Get_processor_name` — ім’я вузла (корисно для діагностики).
- `MPI_Wtime` / `MPI_Wtick` — час і крок годинника для **вимірювання тривалості** (важливо для дослідження ефективності).
- `MPI_Abort` — аварійне завершення всіх процесів (типово при помилці).

### Point-to-point (один-до-одного)

- Передача лише між **двома** процесами.
- Режими: блокуючі / неблокуючі send і recv; також buffered, synchronous, ready тощо. **Будь-який** тип надсилання можна поєднувати з **будь-яким** типом прийому.

## 3. Блокуючі методи (лекція 2.3)

### Загальні правила передачі

- Повідомлення — набір **однотипних** елементів (**буфер**); `count` задає кількість елементів, не байти.
- **Тип MPI** (`MPI_DOUBLE`, `MPI_INT`, …) має відповідати типу даних у програмі; компілятор це **не перевіряє**.
- Розмір буфера отримувача має вміщувати всі надіслані елементи.
- Логічні кроки: відправник зчитує буфер → повідомлення в мережевих/системних буферах → отримувач записує у свій буфер.
- **Тег** — ціле (у матеріалі: до 32767) для розрізнення повідомлень; `MPI_ANY_TAG` — прийом з будь-яким тегом.
- **Джерело:** `MPI_ANY_SOURCE` — прийом від будь-якого процесу.
- **`MPI_Status`:** після `MPI_Recv` містить `MPI_SOURCE`, `MPI_TAG`, `MPI_ERROR`; якщо використовували `ANY_*`, статус обов’язковий для уточнення; інакше можна `MPI_STATUS_IGNORE`.

### `MPI_Send` / `MPI_Recv`

- **`MPI_Send`**: повертає керування, коли дані **скопійовані** у буфер повідомлень на стороні, що дозволяє завершити операцію (часто — буфер отримувача або системний буфер); **не** гарантує, що отримувач уже прочитав у свій масив.
- **`MPI_Recv`**: блокується, доки відповідне повідомлення (за джерелом, тегом, комунікатором) **не прийняте повністю** у буфер програми; після повернення дані в буфері валідні.

Сигнатури (C):

```text
int MPI_Send(void* buf, int count, MPI_Datatype datatype, int dest, int tag, MPI_Comm comm);
int MPI_Recv(void* buf, int count, MPI_Datatype datatype, int source, int tag, MPI_Comm comm, MPI_Status *status);
```

### Паралельне множення матриць (схема з лекції / завдання)

- **Master (ранг 0):** ініціалізує матриці $A$, $B$; ділить **рядки $A$** між $N-1$ робочими процесами (з урахуванням залишку від ділення); для кожного робочого надсилає: зсув по рядках, кількість рядків, блок $A$, повну матрицю $B$ (кожен робочий потребує весь $B$ для своїх рядків $C$).
- **Робочі:** приймають параметри та дані; обчислюють відповідний фрагмент $C$ (рядки $C$ = рядки $A$ × $B$); надсилають назад master зсув, кількість рядків і блок $C$.
- **Master:** збирає фрагменти $C$ і (опційно) виводить результат.

Це **розподіл за рядками $A$** з **трансляцією $B$** до кожного робочого — типова навчальна схема для MPI point-to-point.

## 4. Неблокуючі методи (лекція 2.4)

- Виклик **не блокує** виконання для завершення передачі: процес може робити інші дії, поки операція **в процесі**.
- Імена операцій **Immediate**: `MPI_Isend`, `MPI_Irecv` тощо.
- Додатковий аргумент **`MPI_Request *request`** — дескриптор операції; завершення — через **`MPI_Wait`** (одна операція) або **`MPI_Waitall`** (кілька).
- Після старту неблокуючої операції **не можна** змінювати / читати буфер, доки не виконано `Wait` / `Waitall` (або еквівалентну синхронізацію).
- **`MPI_Irecv`** не приймає `status` у виклику; інформацію про прийом можна отримати через `MPI_Wait` → `status` або `MPI_Test`.
- **Важливо:** блокуюче надсилання можна приймати неблокуючим прийомом і навпаки — режими send/recv **незалежні** на рівні семантики поєднання.

Сигнатури (C):

```text
int MPI_Isend(void *buf, int count, MPI_Datatype datatype, int dest, int tag, MPI_Comm comm, MPI_Request *request);
int MPI_Irecv(void *buf, int count, MPI_Datatype datatype, int source, int tag, MPI_Comm comm, MPI_Request *request);
int MPI_Wait(MPI_Request *request, MPI_Status *status);
int MPI_Waitall(int count, MPI_Request array_of_requests[], MPI_Status array_of_statuses[]);
```

Додатково згадуються варіанти: `MPI_IBsend`, `MPI_ISsend`, `MPI_IRsend` та відповідні recv — для лабораторної роботи зазвичай достатньо стандартних `Isend`/`Irecv` + `Wait`/`Waitall`.
